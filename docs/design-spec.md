## 1. 목적과 우선순위

처음 쓰는 동기도 기록을 읽고, AI 제안을 검토하고, 자기 언어로 다듬어 서사 문서 한 개를 만들 수 있어야 한다. 결과의 감동보다 날짜 있는 장면, 반복된 강점, 남이 본 나, 고비, 3인칭·1인칭 두 판의 보존이 중요하다. 과제는 8~10시간의 작업이며, AI 생성이 끝났다고 과제가 끝난 것으로 표현하지 않는다.

우선순위는 과제 규칙 → 사람만 하는 일 → 합의한 사용자 결정 → 접근성과 가독성 → 시각적 정교함이다. Emil Kowalski 원칙은 브리프에 명시된 절제, 타이포그래피 중심, 목적 있는 150~250ms ease-out, 분명한 상호작용 상태로 적용한다. 외부 사례를 새로 수집하거나 검증한 것으로 주장하지 않는다.


### 기존 기능에서 유지·수정할 것

두 버전의 파일 입력, 기본 규칙 다섯, 후보 10개 생성, 3개 이상 선택, 강점 표, 삭제 이유 기록, 3인칭 초안·1인칭 판, 동료 답 네 칸, 자기소개서, 판단 세 줄, MD 저장·복사는 유지한다. 현재 버전의 데스크톱 왼쪽 단계 메뉴와 차분한 타이포그래피 방향도 유지한다.

다만 다음은 기존 구현보다 브리프가 우선한다.

- 460~480px 높이의 내부 스크롤 기록 상자를 없애고 본문 페이지에서 읽는다. 기존 14px 본문과 작은 입력 글자는 키운다.
- 모든 단계가 연속으로 펼쳐지는 구조를 작업별 마법사형으로 바꾼다.
- 노랑·초록·분홍/보라 형광 배경을 아래의 옅은 배경·선·이름표로 교체한다.
- 동료 이름 가리기 입력칸과 그 입력을 요구하는 안내를 없앤다. 파일의 사전 가림을 이용하며 최종 문서 전체를 사람이 다시 확인한다.
- 두 HTML의 AI 문맥에는 직접 표시한 대목이 들어간다. 새 설계에서는 모든 AI 요청에서 표시 데이터와 비교 결과를 제외한다.
- 예시 기록과 표시를 처음부터 내 작업처럼 채워 두지 않는다. 예시가 필요하면 별도 둘러보기로 명시하고 실제 제출 데이터와 섞지 않는다.
- ‘기록에 없는 사실을 지어내지 않는다’와 규칙 ④의 충돌을 숨기지 않는다. 규칙 ④의 서사 보완은 과제 요구로 유지하고 [채움] 이름표로 검토하게 한다. 사람 전용 칸을 보완하는 권한으로 확대하지 않는다.

## 2. 정보 구조와 공통 동작

**한 단계씩 보여 주는 마법사형**을 택한다. 긴 한 페이지는 지금 해야 할 일과 다음 할 일을 섞고, 모바일에서 되돌아가기 어렵다. 여섯 단계는 브리프의 카드 다섯 + 최종 점검이며, 첫 파일 올리기는 1단계의 시작 상태다.

흐름: 파일 올리기 → 1 기록 읽고 표시 → 2 규칙 다듬기 → 3 강점 지도 → 4 회복탄력성 → 5 자기소개서·포트폴리오 → 6 점검·저장. 복잡한 3·4·5단계 안에서는 아래에 정의한 작은 작업 화면으로 나누되 왼쪽 단계 번호는 유지한다. 각 작은 작업 위에 현재 위치를 표시한다. 3A/3B/3C는 ‘3단계 중 1번째/2번째/3번째’, 4A/4B/4C도 같은 방식, 5A/5B는 ‘2단계 중 1번째/2번째’로 표시한다. 현재 작업만 펼치고 완료 내용은 요약·다시 보기로 제공한다.

데스크톱 1000px 이상: 전체 최대 1440px, 좌측 단계 메뉴 176px, 메뉴와 작업 간 24px, 작업은 남은 폭. 1000px에서 안쪽 폭 968px를 기준으로 작업 폭은 약 768px다. 기록 화면 안에서는 본문 최소 480px + 간격 20px + 표시 패널 240px를 우선한다. 더 넓을 때 본문은 약 680px까지 늘리고 남는 폭을 여백으로 쓴다. 서술 편집 화면은 단일 열 최대 760px다. 표 화면은 작업 영역 전체를 쓴다.

400px: 좌우 16px로 실사용 폭 368px. 상단에는 ‘3/6 강점 지도’와 ‘단계 목록’ 버튼, 열면 여섯 항목이 세로로 펼쳐진다. 가로 스크롤 단계 탭은 쓰지 않는다. 주 버튼은 폭 100%, 보조 이동은 글자 버튼이다. 하단 고정 버튼은 기본으로 쓰지 않아 키보드·본문을 가리지 않는다. 600~999px도 단일 열로 안전하게 전환한다.

각 작업 화면에는 제목 → ‘지금 할 일’ 한 줄 → 작업 → 주 버튼 하나 순서가 있다. 작업 상태가 바뀌면 주 버튼의 역할도 바뀐다. 예를 들어 후보 생성 전에는 ‘후보 10개 받기’, 생성 후에는 ‘고른 강점으로 표 만들기’만 강조한다. ‘이전’, ‘나중에 이어 하기’, ‘원문 보기’는 보조 버튼이다. 표의 삭제 입력이 열렸을 때만 그 영역의 ‘이유 남기고 지우기’를 주 동작으로 바꾸고 바깥 주 버튼 강조를 내린다.

단계 이동은 입력을 잃지 않는다. 미완료 단계도 살펴볼 수 있으나 AI 실행의 필수 재료가 없으면 해당 칸으로 안내한다. 단계 메뉴는 필요한 작성과 확인이 끝나면 ‘완료’ 하나로 표시한다. 이전 자료 변경 시 뒤 단계에 ‘앞 내용이 바뀌었습니다. 다시 확인해 주세요’를 표시하고 자동 재생성·덮어쓰기를 하지 않는다.

### 작성 주체의 시각적 문법

| 구분 | 표시와 동작 |
|---|---|
| 사람이 직접 작성 | `직접 작성 · 필수` 글자 이름표, 실선 테두리, field 배경, 항상 보이는 레이블. AI 채우기·고쳐 주기 버튼 없음 |
| AI 결과 | `AI 초안 · 검토 전` 이름표, surface 배경과 상단 얇은 구분선, 원문 날짜 링크. 검토 후 `내가 검토함` 표시 |
| 기본 제공 문장 | `기본 문장 · 내 말로 수정` 이름표. 사람이 편집하는 규칙이며 AI 결과처럼 취급하지 않음 |
| 파일에서 읽음 | `파일에서 가져옴` 이름표. 이름은 수정 가능, 기록 원문은 읽기 전용 |
| 구조 자동 정리 | `입력한 내용으로 구성` 이름표. 포트폴리오 목차·확인 방법·AI 사용 이력만 사실 그대로 조합 |

색 외에도 이름표·레이블·선으로 구분한다. AI 결과는 사람이 검토·수정할 수 있으며 별도의 변경 이력은 추적하지 않는다. 사람 전용 칸은 프롬프트 결과의 쓰기 대상에서 구조적으로 제외한다.

## 3. 화면별 와이어프레임과 행동

표기: `[직접: …]`은 사람 전용 칸, `{AI: …}`는 AI 초안, `(구조: …)`는 입력 기반 구성, `[주: …]`는 현재 화면의 유일한 강조 버튼이다. 모든 도식의 메뉴·헤더는 공통 동작을 따른다. 도식의 예시 문구는 실제 입력값을 미리 채우라는 뜻이 아니다.

### 0. 처음 열기 / 1단계 파일 올리기

지금 할 일: **내 리추얼 기록 JSON 파일을 올려 주세요.** 주 버튼: ‘기록 파일 선택’. AI 칸 없음.

처음 5초에는 제목·이 도구로 하는 일 3줄·전체 6단계 안내·파일 선택이 보인다. 3줄은 ① 기록을 읽고 표시 ② AI가 강점과 이야기 초안을 뽑음 ③ 내가 고르고 다듬어 제출 문서 저장이다. 긴 과제 설명과 전체 기준표는 접힌 ‘과제 안내’ 안으로 보낸다. 파일을 읽으면 실제 개수로 ‘35일 · 아침 35 · 마무리 35’, 파일명, 학생 이름 자동 입력과 수정칸을 보여 준다. 이때 주 버튼은 ‘기록 읽기 시작’으로 교체한다. `student`가 비면 이름을 직접 입력하도록 알린다. 35일을 하드코딩하지 않는다.

JSON 파싱·구조 오류는 선택 영역 아래에 ‘기록을 읽지 못했어요. student와 days가 있는 JSON인지 확인해 주세요.’로 표시한다. 잘못된 파일이 기존 작업을 지우지 않는다. 파일 교체는 영향을 받을 기록·표시·AI 결과 범위를 인라인 확인으로 알려 준 뒤 사용자가 선택한다. 동료 이름 입력칸은 없다.

### 1. 기록 읽기

지금 할 일: **기록을 읽고 기억에 남는 대목을 직접 표시하세요.** 주 버튼: ‘표시를 마치고 규칙으로’. AI 칸 없음. 표시 최소 개수는 임의로 강제하지 않으며 C02를 위해 날짜 있는 대목은 필요하다.

```text
데스크톱 >=1000px
┌단계┬───────────────────────────┬─────────────────┐
│1 현재│ 기록 읽기   날짜 [09-08 v] │표시한 대목 3개  │
│2     │ 지금 할 일: 읽고 직접 표시│되풀이 1 / 힘 1  │
│3     │ 표시 종류 [되풀이][힘][놀람]│놀람 1           │
│4     │┌2026-09-08───────────────┐│09-08 · 되풀이   │
│5     ││아침                    ││「원문 대목…」   │

│      │[주: 표시를 마치고 규칙으로]│                 │

모바일 400px
┌──────────────────────────┐
│1/6 기록 읽기    단계 목록 │

│다음 날짜 카드…            │
│표시 목록 펼침 / 기록 이동 │
```

날짜 카드 하나 안에 아침(open)·마무리(close)를 세로로 둔다. 항목 13개·8개를 누락하거나 요약하지 않고 원문 순서를 유지한다. 첫 구분 콜론을 기준으로 질문·답을 나누며 답 내부의 콜론은 보존한다. 질문 16px/400·muted, 답 18px/500(모바일 17px), 줄 높이 1.85. ‘흐리게’는 낮은 불투명도가 아닌 대비를 충족하는 보조 글자색이다. 질문도 읽을 수 있어야 한다. 긴 답은 임의 말줄임하지 않는다. 없는 아침/마무리는 ‘이 날짜의 아침 기록이 없습니다’로 표시하고 생성하지 않는다.

페이지 자체를 스크롤한다. 본문에 max-height와 overflow-y를 주지 않는다. 날짜 바로가기는 실제 날짜 목록의 레이블 있는 select와 이전/다음 날짜 버튼으로 제공한다. 이동 시 해당 날짜 제목에 포커스를 보내고 상단 도구 아래로 보이게 한다. ‘현재 날짜 12/35’는 위치 정보이며 읽기 완료 판정이 아니다.

표시는 답의 문장 또는 원본 항목 단위로 한다. 화면 위의 세 종류 선택기에서 현재 종류 하나를 고른 뒤 항목을 한 번 누르면 그 종류로 표시하고 다시 누르면 해제한다. 종류 변경은 표시된 항목의 작은 메뉴에서 한다. 키보드 Enter·Space와 터치에서 같은 동작을 제공하고 종류 선택기는 방향키·Space로 조작한다. 원문 선택·복사를 방해하지 않으며 드래그 선택을 필수로 하지 않는다. 표시 후 4px 왼쪽 선, 옅은 배경, 글자 이름표를 붙인다. 한 대목은 한 종류이며 종류 변경은 새 항목 추가로 세지 않는다.

표시한 대목 패널은 날짜·아침/마무리·종류·원문 미리보기·‘기록으로 이동’·‘표시 해제’를 제공한다. 원문 위치는 날짜+파트+항목 식별자로 보존하며 날짜가 같다는 이유로 다른 항목으로 이동하지 않는다. 데스크톱 옆 패널은 sticky이고 목록 전체는 페이지 흐름에서 펼친다. 모바일은 본문 위에 개수와 접이식 진입점을 항상 제공하고 목록은 아래에 둔다. 진입점을 열면 목록 제목으로, 목록에서 이동하면 정확한 원문으로 포커스를 옮긴다. 패널로 돌아가기 보조 링크도 제공한다. 이동 대상은 200ms 테두리 강조 후 정착하며 색 번쩍임은 없다.

미리 채울 다섯 내용은 ① 형용사 대신 날짜 붙은 장면 ② 여러 날 되풀이 우선 ③ 내가 본 나와 동료가 본 나 나란히 ④ 기록이 없는 시점·사건도 서사로 채우기 ⑤ ‘○○ 님은’으로 시작하는 3인칭이다. ④의 의미를 삭제하거나 ‘무조건 빈칸’으로 바꾸지 않는다. [채움]을 붙여 실제 기록과 구분하고 강점 표·이야기에서 사람이 지울 수 있게 한다. 우선순위는 기본 예시 ‘④ → ① → ② → ③ → ⑤’를 제공하되 사람이 편집한다.

기본 문장 그대로인 항목에는 ‘기본 문장입니다. 내 말로 조금 고쳐 보세요.’를 보여 주고 다음 이동을 막지 않는다. 다섯 개 미만·빈 우선순위는 누락으로 알린다. 단순 문자열 패턴만으로 C04의 의미 충족을 확정하지 않는다. AI로 규칙 다시 쓰기는 제공하지 않는다.

### 3. 강점 지도: 후보 → 선택 → 표 → 삭제·비교

3A 지금 할 일: **기록 전체에서 강점 후보 10개를 받아 보세요.** 주 버튼: ‘강점 후보 10개 받기’. 과제 목록은 직접 ‘번호: 제목/만든 것’을 한 줄씩 입력하는 접이식 보조 영역으로 둔다. 실제 목록 없이 산출물을 AI가 지어내지 않는다.

3B 지금 할 일: **후보 중 나를 잘 보여 주는 강점을 3개 이상 고르세요.** 주 버튼: ‘고른 강점으로 표 만들기’. 선택 개수 0/3 이상을 표시하고 3개 선택 때 자동 이동하지 않는다. 4개 이상도 허용하며 자기소개서에서는 대표 셋을 사람이 정한다.

3C 지금 할 일: **표를 원문과 대조해 아닌 내용을 지우고 이유를 남기세요.** 주 버튼: ‘검토를 마치고 회복탄력성으로’.

```text
데스크톱 (3A/3B)
┌단계┬─────────────────────────────────────┐
│3 현재│ 후보 받기 > 직접 선택 > 표 검토       │

│      │ {AI: □ 강점명 · 4일 · 날짜들}         │
│      │ {대표 장면 · 원문 보기} × 10, 세로    │
│      │ 직접 선택 3개                        │
│      │[주: 고른 강점으로 표 만들기]         │
└──────┴─────────────────────────────────────┘
모바일 400px (3A/3B)
┌────────────────────────┐
│3/6 강점 지도 단계 목록 │
│3단계 중 2번째 · 직접 선택│
│직접 선택 2개 / 3개 이상 │

┌단계┬────────────────────────────────────────┐
│3 현재│ 3단계 중 3번째 · 표 검토                 │
│      │ [강점 표] [AI 강점 ↔ 내 표시]            │
│      │강점│날짜 장면│동료 말/느낌│가치│과제     │

│      ││[직접: 지우는 이유 · 필수]            │ │
│      ││[주: 이유 남기고 지우기]  취소        │ │
│      │└───────────────────────────────────┘ │
│      │지운 항목과 이유 / 되돌리기              │
│      │(삭제창 닫힌 뒤) [주: 검토를 마치고 다음]│
```

표는 강점명·날짜 있는 장면·동료 말/자신의 느낌·지킨 가치·1~8번 과제의 다섯 열이다. 데스크톱·모바일 모두 사용자가 입력한 1~8번 목록 안에서만 AI가 연결을 제안하고 사용자는 검토·수정·지우기를 한다. 목록에 없는 제목은 만들지 않으며 목록이 없으면 입력을 안내한다. 1000px에서 열이 지나치게 좁으면 읽기용 표와 선택한 행의 전체 폭 편집기를 분리한다. 400px는 각 행을 레이블 있는 세로 카드로 전환해 같은 데이터를 제공한다. 가로 스크롤로 감추거나 글자를 줄이지 않는다. 반복 횟수는 언급 횟수 대신 근거가 된 서로 다른 날짜 수를 표기하고 근거 날짜를 열어 확인하게 한다.

삭제는 칸 또는 강점 전체를 대상으로 한다. 해당 원문과 강점명을 보여 주고 **이유를 직접 한 줄 적기 전에는 삭제를 확정하지 않는다**. 이유 예시는 placeholder에만 두고 자동 선택·자동 작성하지 않는다. 확정하면 삭제 전 내용·대상·직접 쓴 이유를 로그에 보존한다. 대상·원문·이유의 삭제 로그만 보존한다. 일반 편집과 복구의 변경 이력은 추적하지 않는다. 되돌리면 해당 삭제를 취소하며 실질 삭제가 없는 상태를 C10 완료로 세지 않는다. C10은 명시적 삭제와 이유가 있는지를 확인한다.

지운 칸은 사람이 기록에서 찾아 채우거나 ‘기록에 없음’으로 둔다. ‘기록에 없음’은 정직한 상태지만 C07의 날짜 장면이나 C09의 실제 과제 연결을 충족하지 않는다. 이 문구가 있다고 ‘됨’으로 처리하지 않는다. C07·C09가 여전히 부족하면 최종 점검에 남긴다. 동료 말이 없으면 ‘자신의 느낌: …’으로 출처를 명시한다. AI는 기록 속 느낌만 인용할 수 있고 사람의 새 느낌을 대신 창작하지 않는다. 강점이 3개 아래로 줄면 추가 선택 안내를 한다. 삭제 실적을 만들려고 틀린 문장을 일부러 생성하지 않는다.

**AI 강점 ↔ 내 표시 비교:** 표 옆 보기 전환으로 세 목록을 제공한다. ‘겹치는 근거’, ‘AI에만 있음 · 지울지 검토’, ‘내 표시에만 있음 · 놓친 대목 검토’. 데스크톱은 AI 근거/내 표시 두 열, 모바일은 같은 날짜의 두 근거를 위아래로 둔다. 각 항목에 정확한 원문 이동과 표의 해당 칸으로 가기를 제공한다. 같은 날짜만으로 겹침이라 판정하지 않고 동일 원문 항목·범위로 연결한다. 연결이 불명확하면 ‘직접 대조 필요’로 둔다. 비교는 로컬 데이터로 하며 자동 삭제·자동 강점 추가·재분석 요청을 하지 않는다.

분석용 AI 요청은 규칙·우선순위와 전체 기록을 기본으로 한다. 표 요청에는 사용자가 선택한 후보와 실제 입력한 산출물, 이야기 요청에는 직접 입력한 고난과 검토한 강점, 자기소개서 요청에는 1인칭 판 등 해당 작업의 재료만 추가한다. **표시 목록·표시 종류·표시 위치·개수·비교 결과는 어느 AI 요청에도 보내지 않는다.** 전체 기록에 같은 문장이 원문으로 들어가는 것은 정상이며 ‘사용자가 표시했다’는 정보가 전송되지 않는 것이 핵심이다.

### 4. 회복탄력성

4B 지금 할 일: **AI 초안을 읽고 내 손으로 1인칭 이야기를 쓰세요.** 주 버튼: ‘내 글을 동료에게 보여 줄 준비 완료’.

4C 지금 할 일: **실제로 들은 두 사람의 답을 이름 없이 적으세요.** 주 버튼: ‘동료 답을 남기고 자기소개서로’.


도식은 작업 상태 목록이며 4A·4B·4C 전체를 동시에 펼치지 않는다. 3인칭은 ‘○○ 님은 …’으로 시작하고 고난 → 다시 일어난 날 → 더 나아진 나 세 부분을 구분한다. 다시 일어난 날은 마무리 ‘못 했다’와 다음 날 변화의 실제 기록을 연결해 확인한다. [채움] 문장은 별도 이름표로 보이며 사람에게 삭제·사실 확인을 요구한다. 과정 이전의 개인 과거를 AI가 새로 만들 수 없다.

원본 3인칭은 항상 별도로 보존한다. 1인칭 칸은 직접 쓰거나 보조 버튼 ‘3인칭 초안을 복사해 와서 지우고 고쳐 쓰기’로 시작할 수 있다. 버튼은 원문을 그대로 복사할 뿐 자동 1인칭 변환·문장 완성을 하지 않는다. 이미 쓴 내용이 있으면 교체 전 인라인 확인을 받는다. 사용자는 초안을 읽고 나답지 않은 문장을 지운 다음 내 손으로 1인칭으로 바꿔 쓴다. 3인칭 읽기 영역 위, 1인칭 편집기 아래를 기본으로 한다. 긴 글 편집기는 16px 이상, 최소 12줄, 세로 확장 가능이며 읽기 미리보기에는 높이 제한이 없다. 1인칭 판이 원본과 거의 같거나 ‘님은’, ‘그는/그녀는’ 같은 표현이 남으면 점검에 ‘확인해 주세요’를 표시한다. 유사도·3인칭 표현 검사는 보조 신호일 뿐 직접 고쳐 썼는지 자동 판정하지 않는다. 글자 수나 문체만 바뀌었다고 완료 처리하지 않고 사람이 내용을 직접 확인한다.

동료는 ‘동료 1’, ‘동료 2’로만 구분하며 각자 ‘나 같은가?’, ‘지어낸 느낌이 있는가?’ 두 답을 적는다. 아직 못 받았다면 ‘답 기다리는 중’으로 보관하되 완료로 세지 않는다. AI 예시 답·자동 요약·삭제 버튼은 없다. 실제로 들은 답의 오타 수정은 허용하되 별도 변경 이력은 추적하지 않는다. 동료 답은 보존하며 AI 재생성이 변경하거나 삭제하지 않는다. 서비스가 메시지를 보내거나 동료 답을 만들어 내는 흐름은 없다.

### 5. 자기소개서·포트폴리오·판단

5A 지금 할 일: **첫 문장과 마지막 문장을 직접 쓰고 본문을 다듬으세요.** 주 버튼: 생성 전 ‘본문 초안 받기’, 검토 후 ‘포트폴리오 확인으로’.

5B 지금 할 일: **강점별 산출물 연결을 확인하고 판단 세 줄을 적으세요.** 주 버튼: ‘최종 점검으로’.

```text
데스크톱
┌단계┬──────────────────────────────────────┐
│5 현재│ 자기소개서 > 포트폴리오·판단          │
│      │5A [직접: 읽는 사람 / 하고 싶은 것]   │
│      │   [직접: 첫 문장 · 필수]            │
│      │   {AI: 본문 / 내가 검토·수정}       │
│      │   [직접: 마지막 문장 · 필수]        │
│      │   합쳐 읽기 / 전체 약 1000자         │
│      │   [주: 포트폴리오 확인으로]          │
│      │5B (구조: 이름 > 소개서 > 강점별 과제)│
│      │   [직접: 판단 세 줄]                │
│      │   [주: 최종 점검으로]               │
└──────┴──────────────────────────────────────┘
모바일 400px
┌──────────────────────────┐
│5/6 자기소개서   단계 목록│
│현재 위치: 2단계 중 1번째│
│[직접: 읽는 사람·희망]    │
│[직접: 첫 문장]          │
│{AI: 본문, 넓은 단일 열} │
│[직접: 마지막 문장]      │
│합쳐 읽기                │
│[주: 포트폴리오 확인으로]│
│다음 작업: 목차·판단 세 줄│
└──────────────────────────┘
```

읽는 사람 기본값은 ‘나를 처음 만나는 사람/동료’. 약 1,000자는 첫 문장+본문+마지막 문장 전체 기준이며 강제 잘라내지 않는다. 이름·대표 강점 셋·고비 한 장면·하고 싶은 것이 들어갔는지 읽기 미리보기 옆 체크로 확인한다. 길면 강점 이름을 빼는 대신 한 강점의 장면을 통째로 줄이거나 빼도록 안내한다. AI는 가운데 본문만 제안하며 첫·마지막 칸을 쓰거나 덮어쓸 수 없다.

포트폴리오는 사이트가 아니라 서사 문서 안 목차다. 이름 → 자기소개서 → 대표 강점 셋 → 각 강점의 실제 1~8번 산출물로 구성한다. 산출물은 한 줄 입력 목록에서 사람이 연결·수정하고 AI가 임의 제목이나 URL을 만들지 않는다. 10번 논문·11번 소설·마지막 과제 대표작은 ‘추후 작성’이라는 빈 자리만 둔다. 이 예정된 빈칸은 누락 경고 대상이 아니다. URL 입력과 별도 포트폴리오 게시 버튼은 없다.

판단 세 줄: ‘AI에게 맡긴 일’은 실제 사용 이력을 보조로 보여 주고 사용자가 원할 때 가져와 확인한다. ‘내가 직접 판단한 일’, ‘AI 제안을 따르지 않은 일(없었다면 이유)’은 사람만 작성한다. 삭제 로그는 읽기 참고로만 보이며 이 두 칸을 자동 작성하지 않는다.

### 6. 최종 점검·저장

지금 할 일: **빠진 항목과 직접 확인할 내용을 살핀 뒤 문서 하나로 저장하세요.** 주 버튼: ‘서사 문서 저장’. 누락 시 같은 버튼은 저장을 실행하지 않고 첫 누락 요약으로 포커스를 옮긴다.

```text
데스크톱
┌단계┬───────────────────────────────────────┐
│6 현재│ 점검·저장                             │
│      │ 됨 16 / 확인해 주세요 3 / 비어 있음 1    │
│      │ C10 지운 이유 없음 [강점 지도로 이동] │
│      │ C26 다른 사람 실명 등 직접 읽기 확인  │
│      │ (구조: 최종 문서 읽기 미리보기)       │
│      │ 형식 [MD v] 파일명 T09_이름.md        │
│      │[주: 서사 문서 저장]  내용 복사        │
│      │ 저장 승인 후: 파일명 / 저장 완료      │
└──────┴───────────────────────────────────────┘
모바일 400px
┌─────────────────────────┐
│6/6 점검·저장  단계 목록 │
│먼저 채울 항목 1개       │
│C10 지운 이유가 없어요. │
│[강점 지도로 이동]       │
│직접 확인할 내용 펼치기 │
│최종 문서 읽기           │
│형식 [MD v]              │
│[주: 서사 문서 저장]     │
│내용 복사 (보조)         │
└─────────────────────────┘
```

누락은 ‘단계명 · 항목명 · 필요한 이유 · 해당 칸으로 이동’으로 제공한다. 예: ‘회복탄력성 · 동료 2의 답이 비었습니다. 실제로 받은 답을 적어 주세요. [답 입력으로]’. 이동 후 칸에 포커스하고 ‘점검으로 돌아가기’를 둔다. 공백을 ‘기록에 없음’으로 일괄 변환하거나 AI로 채우지 않는다.

점검 상태는 ‘됨’, ‘확인해 주세요’, ‘비어 있음’ 세 가지뿐이다. 자동 검사는 존재·개수·날짜 형식을 확인할 뿐 사실성을 보증하지 않는다. C11·C14·C26 등은 입력이 있어도 실제 문서에서 내용·개인정보를 직접 확인해야 하며 그전에는 ‘확인해 주세요’로 표시한다. ‘기록에 없음’은 C07·C09 충족이 아니다. 유사도·남은 3인칭 표현 검사는 보조 신호로만 쓰며 직접 고쳐 썼는지 자동 판정하지 않는다. 연락처·키 의심 값은 재노출하지 않고 위치와 종류를 알린다. 실명 검사에는 한계가 있으므로 이름 입력칸 대신 문서 전체 읽기를 안내한다.

저장 결과는 UTF-8 MD 한 개가 기본이고 TXT 선택은 같은 내용을 읽기 쉬운 텍스트로 구성한다. 형식을 선택한 뒤 주 버튼 한 번으로 파일 한 개를 저장한다. 다운로드 승인 취소를 완료로 표시하지 않는다. 사용자 승인·실제 반환 성공 뒤에만 ‘저장했습니다. T09_이름.md’를 보여 준다. 파일 이름에 키·연락처가 들어가지 않게 하고 비밀번호·압축·로그인을 요구하지 않는다.

**저장 파일 구성 순서**

1. 문서 첫머리: 본인 이름·과제 제목.
2. 직접 고른 기록 대목: 날짜·아침/마무리·표시 종류·원문. 이름 다음에 바로 두어 ‘맨 앞’ 요구를 지킨다.
3. 에이전트 규칙 다섯 이상과 우선순위.
4. 강점 지도 표, 직접 지운 내용과 이유, 직접 수정한 근거. ‘기록에 없음’ 상태도 사실대로 보존.
5. 회복탄력성: 직접 쓴 고난 재료, AI 3인칭 초안, 사람이 쓴 1인칭 완성본, 동료 두 사람의 이름 없는 답. 두 판 모두 보존.
6. 자기소개서: 직접 첫 문장 + 검토한 본문 + 직접 마지막 문장.
7. 포트폴리오 뼈대: 이름·소개서 위치·대표 강점 셋과 산출물·미래 과제 빈 자리.
8. AI에게 맡긴 일 / 내가 직접 판단한 일 / 따르지 않은 일 또는 없었던 이유.
9. 짧은 확인 방법: ‘자기소개서: 6절, 강점 지도: 4절, 두 판의 이야기: 5절’처럼 최종 출력의 실제 제목·번호와 일치하게 구성.

표의 줄바꿈·세로 막대는 내보내기 형식에 맞게 처리한다. 원본 기록 전체·불필요한 디버그 로그·API 관련 값은 제출 파일에 넣지 않는다. 원본에 없는 날짜를 넣어 C07을 맞추지 않는다.

## 4. 대기·실패·복구 상태

| 상태 | 표시·행동·복구 |
|---|---|
| AI 실행 전 | ‘이 요청은 내 Claude 계정 사용량을 사용합니다. 첫 요청 때 동의 창이 열립니다.’ 요청 버튼 주변에 한 번 명확히 표시. 페이지를 열자마자 자동 요청하지 않음 |
| 0~5초 | ‘기록을 읽고 있습니다. 보통 5~60초 걸립니다.’ 정적인 상태 이름과 경과 초, 중지 버튼. 중복 실행만 비활성화 |
| 5~30초 | 응답이 오면 ‘초안을 쓰고 있습니다’. 스트리밍 문장은 AI 초안 영역에만 반영. 전체 화면을 막지 않음 |
| 30~60초 | ‘아직 작성 중입니다. 중지해도 직접 쓴 내용은 남습니다.’ 거짓 백분율·가짜 단계·추정 잔여 초 없음 |
| 60초 초과 | ‘평소보다 오래 걸립니다.’ 중지와 계속 기다리기 선택. 60초에 무조건 실패 처리하지 않음 |
| 중지 | 요청마다 AbortController를 두고 sample에 signal을 전달한다. 중지를 누르면 abort()로 요청 자체를 끊고 ‘요청을 중지했습니다. 직접 쓴 내용은 남아 있습니다.’를 표시한다. 중지는 연결 오류와 구분하며 늦은 응답도 반영하지 않는다 |
| 부분 초안 | 현재 AI 칸에 ‘미완성 초안’으로 표시하며 완료 처리하지 않는다. 별도 판 선택은 없고 재시도 전 교체 여부를 한 줄로 확인한다 |
| 연결·권한·한도 오류 | 이유를 쉬운 말로 표시, 입력 보존, 재시도 보조 버튼. 같은 요청을 자동 반복하지 않음 |
| 잘못된 AI JSON / 빈 답 | ‘후보를 읽지 못했습니다. 기존 표는 그대로 있습니다.’ 검증 실패 결과가 현재 작업을 덮어쓰지 않음 |
| 요청 길이 초과 | 실제 기록은 약 3만 2천 자라 보통 한 번에 들어간다. 파일이 너무 길면 공식 안내에 따라 최근 30일을 먼저 넣고 나머지는 두 번째 대화에 넣은 뒤 결과를 합친다. 두 요청에 같은 규칙을 적용하고 날짜 범위를 표시해 전체 범위를 보존한다. 중복 근거는 합치고 한쪽만 끝난 상태는 전체 완료로 표시하지 않는다 |
| AI 사용 불가(null)/동의 거절 | ‘여기서는 AI를 사용할 수 없습니다. 기록 읽기와 문서 정리는 계속할 수 있습니다.’ AI 대상 영역에는 직접 입력·다른 AI에서 받은 실제 결과 붙여넣기 제공. 후보·3인칭 AI 판을 사람이 쓴 것으로 속여 완료 처리하지 않음 |
| AI 재생성 | ‘다시 받기’ 전에 ‘현재 AI 초안을 새 응답으로 바꿉니다.’라는 인라인 확인 한 줄을 제공한다. 성공한 새 응답은 해당 AI 칸만 교체한다. 사람 전용 칸·삭제 로그·동료 답은 절대 건드리지 않으며 첫 3인칭 초안은 원본으로 따로 보존하고 다시 받은 결과는 현재 AI 칸에 표시한다. 다중 판 선택과 변경 이력 추적은 없다 |
| localStorage 실패 | ‘이 브라우저에 임시 저장하지 못했습니다. 창을 닫기 전에 내용을 복사해 주세요.’ 메모리에서 계속 동작. 저장됨 표시를 거짓으로 내지 않음 |
| 저장 실패/미지원 | ‘파일 저장을 마치지 못했습니다. 내용을 복사해 메모장에 붙여넣고 .md로 저장해 주세요.’ 이 상태에서는 ‘문서 내용 복사’를 주 버튼으로 전환 |
| 복사 권한 실패 | 전체 문서를 선택 가능한 큰 텍스트 영역에 열고 ‘전체 선택’ 및 Ctrl+C / ⌘C / 모바일 길게 누르기 안내. 복사 성공 전 ‘복사했습니다’ 금지 |
| 초기화 | 설정 하단에 저강도 ‘이 브라우저의 작업 지우기’. 인라인 확인에 범위 명시, 취소와 삭제 제공. alert/confirm 사용 안 함 |

AI가 없는 환경에서도 업로드·표시·규칙·직접 작성·검토·복사와 저장 지원 여부 안내가 동작한다. AI를 쓸 수 없음이 과제의 AI 산출물 요구를 면제하는 것은 아니므로, 미충족 기준은 남겨 둔다.

## 5. 비주얼 시스템

### 표시 세 종류: 배경 / 왼쪽 선 / 글자

각 표시는 명시적인 이름표를 항상 포함한다. 표의 글자색은 본문과 이름표 모두에 적용하며 이름표 배경도 같은 옅은 배경이다. 선은 4px, 모서리 3px, 안쪽 여백 12px. 초록 형광색·불투명도 중첩·텍스트 위 색 오버레이를 쓰지 않는다.

| 종류 | 라이트 배경 / 선 / 글자 | 다크 배경 / 선 / 글자 |
|---|---|---|
| 되풀이되는 말 | #FFF7E8 / #805400 / #493100 | #2B251A / #D5AE64 / #F4DFC0 |
| 힘이 난 날 | #EDF7F3 / #28634D / #173F31 | #1B2C26 / #7BC8A4 / #D4F0E2 |
| 놀란 순간 | #F3F0FA / #65508B / #3D2D59 | #282232 / #B6A0D8 / #EBE0FA |

문서 작성 중 PowerShell로 위 여섯 조합의 sRGB 대비를 계산했다. 글자/배경은 10.72~12.14:1, 선/배경은 6.07~7.42:1, 선/surface는 6.59~8.42:1이다. 각 글자/자기 배경은 최소 4.5:1, 선/자기 배경과 선/주변 surface는 최소 3:1이 기준이다. 옅은 배경 자체는 surface와 3:1일 필요가 없으며 의미 경계는 선과 이름표가 담당한다. 배경과 글자 중 하나만 다른 테마 값으로 섞지 않는다. 실제 적용 시 hover·focus·선택 중에도 같은 기준을 측정하고 유지한다.

### 글꼴·크기·리듬

Google Fonts 이름은 **Noto Sans KR**(400/500/600/700), 코드·날짜의 보조 글꼴은 **IBM Plex Mono**(400/500). 대체 순서는 본문 `Noto Sans KR → Malgun Gothic → Apple SD Gothic Neo → system-ui → sans-serif`, 숫자 `IBM Plex Mono → Cascadia Mono → Consolas → monospace`. 한글 긴 본문에는 모노스페이스를 쓰지 않는다. Google Fonts를 못 불러와도 같은 구조로 읽혀야 한다. 이번 문서 작업에서는 폰트를 다운로드하지 않는다.

| 단계 | 데스크톱 / 모바일 | 굵기·줄 높이 |
|---|---|---|
| 첫 제목 | 32 / 28px | 700 / 1.35 |
| 단계 제목 | 26 / 24px | 600 / 1.4 |
| 하위 제목·날짜 | 20 / 20px | 600 / 1.5 |
| 기록 답·이야기 읽기 | 18 / 17px | 400~500 / 1.85 |
| 본문·입력·질문 | 16 / 16px | 400, 레이블 500 / 1.7~1.85 |
| 도움말·기준 코드 | 14 / 14px | 400 / 1.6 |

한글 본문 자간은 0~-0.01em, 제목 -0.02em까지. 기존의 과도한 음수 자간은 피한다. 날짜·개수는 tabular-nums. 본문은 왼쪽 정렬, 장문 한 줄은 약 30~40 한글 글자 수준으로 조절한다. 긴 URL·식별자·파일명은 줄바꿈하며 본문 전체에 word-break:break-all을 적용하지 않는다.

간격 단계는 4, 8, 12, 16, 20, 24, 32, 48, 64px. 레이블-입력 8, 도움말 8, 필드 사이 24, 작업 묶음 사이 32, 단계 헤더 아래 24. 카드 내부 24px(모바일 16px), 날짜 사이 32px. 터치 목표 최소 44×44px, 인접 작은 조작 간 8px. 체크박스 도형은 18~20px여도 레이블 전체가 클릭 영역이다.

모서리는 입력·버튼 6px, 날짜 카드 8px, 팝오버 10px, 표와 문서 구분 영역 0~4px다. 모든 것을 알약·큰 둥근 카드로 만들지 않는다. 기본 카드에는 그림자 없이 1px 구분선, 떠 있는 메뉴에만 0 4px 16px shadow를 준다. 이모지 장식·그라데이션·사진·히어로 일러스트는 필요하지 않다.

### 모션

기본 easing은 ease-out 또는 cubic-bezier(0.23, 1, 0.32, 1). hover/focus 색 변화 150ms, 접이식 전환 180ms, 단계 콘텐츠 교체·위치 안내 200ms, 팝오버 180ms. 메뉴 출현 이동은 최대 4px이며 필요할 때만 쓴다. active는 색과 1px 눌림 정도로 150ms, 텍스트 scale 효과는 쓰지 않는다.

장문 스트리밍에 글자별 타이핑 애니메이션, 페이지 진입 순차 등장, 반복 튀기기, 카드 이동 장식, 가짜 로딩 바를 쓰지 않는다. AI 대기는 텍스트 상태와 실제 경과 시간으로 충분하다. prefers-reduced-motion에서는 전환·이동·부드러운 스크롤을 끄고 즉시 상태를 바꾼다. 어떤 모션도 입력·중지·읽기를 지연시키지 않는다.

## 7. 마이크로카피와 기준 코드 노출

행동을 먼저 말하고 문장은 짧게 쓴다. ‘분석 파이프라인’, ‘페르소나’, ‘매핑’ 같은 구현 용어 대신 ‘기록’, ‘원문’, ‘강점 표’, ‘연결’을 쓴다. 성격을 단정하거나 평가하지 않고 다음 한 동작을 안내한다. 완료하지 않은 일을 ‘완벽’, ‘통과 보장’으로 말하지 않는다. placeholder는 예시이며 레이블을 대신하지 않는다.

| 상황 | 주요 문구 |
|---|---|
| 첫 진입 | ‘내 리추얼 기록을 올려 주세요. 읽고 표시하는 일부터 시작합니다.’ |

## 9. 브리프 8장 기술 제약 준수

| 제약 | 설계·구현 인계 원칙 |
|---|---|
| 단일 HTML 조각 | 후속 구현은 title·claude:viewport-fit-sides meta를 맨 위에 두고 html/head/body 없이 내용·스타일·동작을 한 파일에 담는다. 이 문서는 구현 파일을 생성하지 않는다 |
| 외부 자원 제한 | 이미지는 쓰지 않고 글자·CSS 선·기본 제어로 구성. Google Fonts 외 스타일시트, 임의 URL·iframe 없음. 외부 스크립트는 가급적 불필요하며 꼭 필요하면 허용 CDN·고정 버전만 |
| 지원하지 않는 브라우저 기능 | alert/confirm/prompt 대신 인라인 확인. 인쇄·a download로 저장하는 경로 없음 |
| AI sample | claude.use('sample') 결과 지원 여부를 확인한 뒤 사용자 실행에만 sample 또는 sample.json 사용. 스트리밍은 AI 영역에만 반영, 요청 식별자로 중지·늦은 결과 방지. 플랫폼이 지원하는 AbortController signal을 전달하고 중지 시 abort()로 요청 자체를 끊음 |
| 파일 저장 | claude.use('downloads')의 save({filename, data}) 사용, 사용자 승인 대기·취소·실패 각각 표시. 복사와 수동 전체 선택 대체 |
| localStorage만 | 서버 계정·DB·다른 기기 동기화 없음. 실패 시 메모리 작업 계속, 임시 저장의 범위를 정확히 고지. AI 요청 때 재료가 AI로 전달된다는 별도 설명을 두어 ‘브라우저 저장’이 ‘절대 외부 전송 없음’으로 오해되지 않게 함 |
| 테마 구조 | bare :root에 라이트. prefers-color-scheme:dark의 :root:not([data-theme="light"])와 :root[data-theme="dark"]에 같은 다크 값·color-scheme:dark. body와 모든 상태 색을 토큰 사용. 페이지 자체의 테마 선택기는 두지 않고 보는 사람의 Claude 설정(data-theme)과 시스템 설정을 따름 |
| 안전 영역·반응형 | 좌우 max(16px, env(safe-area-inset-left/right, 0px)), 세로 padding-block. sticky 메뉴·도구의 top에 env(safe-area-inset-top, 0px) 더함. 콘텐츠 min-width:0, 표 카드 전환, 긴 문자열 줄바꿈. 400px 가로 스크롤 없음 |
| 접근성 | focus-visible 외곽선, 레이블·상태 이름표, 키보드 동작, prefers-reduced-motion. 대비가 낮은 회색으로 질문을 숨기지 않음 |
| 시각 금지 사항 | 크림/테라코타 세리프·보라파랑 그라데이션·이모지 장식·일괄 중앙 정렬·동일 그림자 카드 없음. 기록과 입력을 왼쪽 정렬 |

### 후속 구현의 인수 확인

처음 쓰는 동기에게 첫 화면을 5초 보여 주고 무엇을 할지 말할 수 있는지 확인한다. 1000px·1440px·400px, 라이트·다크, 글자 확대 200%, 키보드만 사용, reduced motion 상태에서 기록 읽기→표시 이동→삭제 이유→점검 복귀→저장/복사까지 확인한다. 원본 35일·아침/마무리와 항목 수가 보존되는지, 모든 AI 요청에서 표시 메타데이터가 빠지는지, 사람 전용 칸이 AI 결과로 바뀌지 않는지를 확인한다. 최근 30일과 나머지 기록의 두 요청 병합·대기 5/30/60초·AbortController 중지 후 늦은 응답·null AI·저장 거절·클립보드 실패·localStorage 실패도 검토한다. 이는 후속 구현의 검증 계획이며 이번 문서 작업에서 UI 실행 검증을 마쳤다는 뜻이 아니다.

## 10. 실제로 확인·활용한 자료와 도구

- `docs/assignment-brief.md`를 UTF-8로 끝까지 읽었다. 사람 전용 작업, 규칙 ④, 사용자 합의 10개, 기술 제약을 설계의 우선 근거로 삼았다.
- `index.html`, `index.v1-codex.html`의 스타일·화면·데이터 파싱·검사·AI 프롬프트·내보내기·이벤트 처리를 끝까지 확인했다. 출력이 잘린 구간은 범위를 나눠 다시 읽었다. 기존 기능을 파악하고 작은 기록 상자·형광 표시·동료 이름 칸·표시가 포함된 프롬프트·자동 완료 판정의 변경점을 도출했다.
- 현재 세션의 `ALL_TOOLS` 목록에서 설치·연결된 Figma MCP의 design context, screenshot, variable definitions, design system 검색, use_figma, diagram 등 디자인 관련 도구를 확인했다. 대상 Figma 파일·노드가 없고 요청 산출물은 로컬 한국어 지침서이므로 Figma 호출·새 파일 생성은 하지 않았다. 접근성·타이포그래피를 자동 감사한 결과가 있다고 주장하지 않는다.
- 설치된 `visualize:visualize`의 SKILL.md를 읽어 제공 범위를 확인했다. 이 작업은 대화형 미리보기 요청이 아니라 문서 작성이며 코드를 쓰지 말라는 지시가 있어 인라인 HTML 시각화를 만들지 않았다. 정적 공간 구조는 Markdown의 ASCII 도식과 표로 표현했다. Figma·Sites·ImageGen으로 별도 산출물을 만들지 않았다.
- PowerShell에서 `codex mcp list`, `codex plugin list`를 시도했으나 codex.ps1 실행 정책으로 실패했다. `codex.cmd`로 재시도했으나 home directory/CODEX_HOME 해석 오류로 두 목록 모두 조회되지 않았다. 실행 정책이나 시스템 설정은 변경하지 않았다. 따라서 CLI에서 전체 설치 목록을 확인했다고 쓰지 않는다. 실제 사용 가능 도구 확인 근거는 세션에 제공된 도구 목록이다.
- 파일 읽기·검색에는 exec_command, PowerShell Get-Content UTF-8, rg를 활용했다. 작업 폴더 아래 AGENTS.md는 발견되지 않았다. 디자인 산출물은 이 문서 하나이며 앱 코드는 수정하지 않았다.
- 표시 세 종류의 라이트·다크 여섯 조합은 PowerShell 상대휘도 계산으로 글자·선 대비를 확인했다. 전체 UI와 모든 상태를 감사한 결과는 아니다. 새 플러그인 설치, 인터넷 검색, 외부 자료·이미지·글꼴 다운로드는 하지 않았다. 직접 활용할 기존 Figma 디자인이나 전용 접근성 감사 결과는 없었다. 비주얼·접근성 값은 위에 명시한 설계 기준이며 후속 구현에서 실제 상태별 측정이 필요하다.
