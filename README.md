# T09. 나를 말하는 에이전트

아침·마무리 리추얼 기록을 재료로 나의 강점과 이야기를 찾고, 내 이름이 들어간 자기소개서 초안과 포트폴리오 뼈대를 **서사 문서 파일 하나**로 정리하는 웹 도구입니다. SKT ALEPH 과정 9번 과제로 만들었습니다.

에이전트가 강점과 이야기를 **뽑아 주고**, 고르고 지우고 다듬는 일은 **사람이** 합니다. 기록에 없는 내용을 AI가 대신 채우지 않도록 사람이 써야 하는 칸과 AI가 채우는 칸을 나눴습니다.

## 사용 흐름

| 단계 | 하는 일 | 누가 |
|---|---|---|
| 1. 기록 읽기 | 리추얼 기록 JSON을 올리고, 되풀이되는 말·힘이 난 날·놀란 순간을 직접 표시 | 사람 |
| 2. 규칙 다섯 | 미리 채운 에이전트 규칙 다섯을 내 말로 다듬고 우선순위 정하기 | 사람 |
| 3. 강점 지도 | 강점 후보 10개 → 3개 이상 고르기 → 표 만들기 → 아닌 것을 지우고 이유 남기기 | AI가 뽑고 사람이 고름 |
| 4. 회복탄력성 | 과정 이전의 고난 적기 → 3인칭 초안 → 1인칭으로 고쳐 쓰기 → 동료 두 사람의 답 | AI 초안, 나머지는 사람 |
| 5. 자기소개서 | 첫 문장·마지막 문장은 직접, 가운데 본문은 AI 초안을 다듬기 / 포트폴리오 뼈대 확인 | 함께 |
| 6. 점검·저장 | 과제 통과 기준(C01~C19, C26) 점검 후 MD 또는 TXT 파일 하나로 저장 | 사람 |

- 표시한 대목은 AI에게 보내지 않습니다. AI가 뽑은 강점과 나란히 놓고 검사하는 기준으로만 씁니다.
- 기록 속 `(이름 가림)`은 항목 안에서 동료A, 동료B로 바꿔 보여 주고, 답이 가림뿐인 항목은 숨깁니다.
- 입력한 내용은 그 브라우저에만 임시로 저장됩니다.

## AI 연결

Claude 아티팩트의 내장 기능(`window.claude.use("sample")`)으로 Claude를 부릅니다. API 키나 서버가 없고, **페이지를 연 사람의 Claude 계정과 사용량**으로 동작합니다.

- AI 기능은 claude.ai 아티팩트로 열었을 때만 동작합니다.
- 다른 곳(예: GitHub Pages)에서 열면 AI 버튼은 꺼지고, 직접 입력과 파일 저장 흐름만 쓸 수 있습니다.

## 파일 구성

```
index.html   화면 뼈대
style.css    디자인 (라이트·다크 테마 토큰, 레이아웃)
app.js       기능 (기록 읽기, 표시, AI 요청, 점검, 문서 만들기)
docs/
  design-spec.md        레이아웃·UX·비주얼 지침서 (Codex 작성, Claude 검토)
  review-decisions.md   코드 점검 합의안 (Codex·Claude 공동 리뷰)
```

`index.html`은 Claude 아티팩트 형식이라 `<!doctype>`, `<html>`, `<head>`, `<body>` 태그 없이 내용만 담고 있습니다. 게시할 때 감싸집니다.

## 만든 과정

- **Claude**: 과제 흐름과 기능, AI 요청문, 통과 기준 점검, 구현
- **Codex**: 레이아웃·디자인 지침서, 디자인, 코드 점검
- 두 AI가 각자 점검한 뒤 합의한 항목만 반영하고, 서로 승인한 뒤 최종본으로 정리했습니다.

개인 리추얼 기록과 이 도구로 만든 제출 문서는 저장소에 포함하지 않습니다.
