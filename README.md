# T09. 나를 말하는 에이전트

**[실행 사이트](https://claude.ai/artifact/AfsHiiQy4GcTfhKeuHJnB3)** · **[소스코드](https://github.com/eldi96/T09_strength-agent)**

> 실행 사이트는 Claude 아티팩트로 게시되어 있습니다. 열 때 Claude 로그인이 필요할 수 있고, AI 분석은 **페이지를 연 사람의 Claude 계정과 사용량**으로 동작합니다. 입력한 기록과 글은 그 브라우저에만 임시로 저장되며 다른 사람에게 보이지 않습니다.

아침·마무리 리추얼 기록을 재료로 나의 강점과 이야기를 찾고, 내 이름이 들어간 자기소개서 초안과 포트폴리오 뼈대를 **서사 문서 파일 하나**로 정리하는 웹 도구입니다. SKT ALEPH 과정 9번 과제로 만들었습니다.

## 1. 프로젝트 목적

리추얼 기록을 AI에 통째로 넣으면 "성실하고 책임감 있는 사람" 같은 평범한 말이 돌아옵니다. 이 도구는 **에이전트가 강점과 이야기를 뽑아 주고, 사람이 고르고 지우고 다듬는** 과정을 단계별로 나눠, 실제로 쓸 자기소개서의 첫 판을 만들게 돕습니다.

- 에이전트는 사람이 다듬은 **규칙 다섯 개**를 따라 기록 전체를 읽습니다.
- 강점마다 **날짜가 있는 장면, 동료가 말한 것, 지킨 가치, 1~8번 과제 산출물**을 근거로 붙입니다.
- 사람이 해야 하는 일(대목 표시, 지우기와 이유, 고난 쓰기, 1인칭으로 고쳐 쓰기, 동료 답, 첫·마지막 문장)은 **AI가 대신 채우지 않습니다.**

## 2. 주요 화면

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 1 | 기록 읽기 | 리추얼 기록 JSON을 올리고, 되풀이되는 말·힘이 난 날·놀란 순간을 직접 표시합니다. 날짜별 카드에 아침과 마무리가 나뉘어 보입니다. |
| 2 | 규칙 다섯 | 미리 채운 에이전트 규칙 ①~⑤를 내 말로 다듬고, 규칙끼리 부딪칠 때의 우선순위를 적습니다. |
| 3 | 강점 지도 | 강점 후보 10개 → 3개 이상 고르기 → 강점 지도 표 → 아닌 칸을 지우고 이유 남기기. "AI 강점 ↔ 내 표시" 비교 보기로 검토합니다. |
| 4 | 회복탄력성 | 과정 이전의 고난(연도·장소·바꾼 것)을 적으면 AI가 3인칭 초안을 쓰고, 내 손으로 1인칭으로 고쳐 쓴 뒤 동료 두 사람의 답을 이름 없이 남깁니다. |
| 5 | 자기소개서 | 첫 문장과 마지막 문장은 직접 쓰고, AI가 제안한 가운데 본문을 다듬습니다. 합쳐 읽기와 포트폴리오 뼈대를 확인합니다. |
| 6 | 점검·저장 | 과제 통과 기준을 점검하고 MD 또는 TXT 파일 하나로 저장합니다. |

## 3. 에이전트 규칙과 기록 처리 기준

| 항목 | 기준 |
| --- | --- |
| 에이전트 규칙 | ① 형용사 대신 날짜 붙은 장면 ② 되풀이된 것 우선 ③ 내가 본 나와 남이 본 나를 나란히 ④ 기록이 없는 부분도 서사로 채우고 `[채움]` 표시 ⑤ 먼저 3인칭으로. 기본 문장을 내 말로 고쳐 씁니다. |
| AI에게 보내는 것 | 규칙과 우선순위, 기록 전체(항목 번호 포함), 1~8번 과제 목록, 각 단계에서 사람이 쓴 재료 |
| AI에게 보내지 않는 것 | **내가 표시한 대목.** 표시는 AI가 제대로 뽑았는지 견주어 보는 기준으로만 씁니다. |
| 동료 이름 | 기록 속 `(이름 가림)`은 항목 안에서 동료A, 동료B로 바꿔 보여 주고, 답이 가림뿐인 항목은 숨깁니다. 글에서는 다른 사람을 이름·성·직함이 아니라 "강사", "동료" 같은 역할로만 씁니다. |
| 글쓰기 | 날짜는 꼭 필요한 장면에만, 기록의 질문 이름과 집계 표현은 자연스러운 문장으로 풀어 쓰고, 사건을 나열하지 않고 원인과 결과가 이어지게 씁니다. |
| 1~8번 과제 연결 | 사용자가 입력한 목록 안에서만 연결합니다. 목록에 없는 과제 제목은 만들지 않습니다. |

## 4. 과제 통과 기준 점검

6단계에서 각 기준을 **체크 / 확인해 주세요 / 비어 있음**으로 보여 주고, 비어 있는 항목은 해당 단계로 바로 이동합니다.

| 기준 | 점검 내용 |
| --- | --- |
| C01·C02 | 문서 첫머리의 이름, 날짜가 붙은 직접 고른 대목 |
| C03~C05 | 규칙 다섯, "기록이 없어도 서사로 채운다" 규칙, 우선순위 한 줄 |
| C06~C10 | 강점 셋 이상, 강점마다 날짜 장면·동료 말 또는 느낌·지킨 가치·과제 번호, 지운 항목과 이유 |
| C11~C13 | 고난·다시 일어난 날·더 나아진 나, 3인칭 초안과 1인칭 완성본, 동료 두 사람의 답 |
| C14·C15 | 자기소개서의 이름·강점 셋·고비 장면·하고 싶은 것, 포트폴리오 뼈대 |
| C17~C19 | 문서 안 확인 방법, 파일 한 개, 문서 속 URL이 로그인 없이 열리는지(GitHub 소스 주소는 경고) |
| C26 | 연락처·키 패턴과 "김 과장님" 같은 성+직함 표현 검출, 최종 문서 직접 읽기 안내 |

AI와 나의 판단 세 줄, 재현·통과 확인 네 가지는 과제 제출 화면에서 직접 작성합니다.

## 5. 저장되는 문서 구성

1. 이름 · 과제 제목
2. 직접 고른 기록 대목 (날짜 · 아침/마무리 · 표시 종류)
3. 에이전트 규칙과 우선순위
4. 강점 지도 표, 내가 지운 항목과 이유
5. 회복탄력성: 고난, 3인칭 초안, 1인칭 완성본, 동료 두 사람의 답
6. 자기소개서 초안
7. 포트폴리오 뼈대 (강점별 1~8번 산출물, 10번 논문·11번 소설·마지막 과제 자리)
8. 확인 방법

## 6. 기술 구성

| 구분 | 내용 | 비고 |

| 화면 | HTML · CSS · JavaScript (프레임워크·빌드 없음) | `index.html`, `style.css`, `app.js` |
| AI | Claude 아티팩트 내장 기능 `window.claude.use("sample")` | API 키·서버 없음, 보는 사람의 Claude 계정 사용 |

| 디자인 | Noto Sans KR · IBM Plex Mono, 라이트·다크 테마 토큰 | 400px 휴대폰 화면 대응 |

## 7. AI 대기·실패 처리

| 상황 | 처리 |
| --- | --- |
| 응답 대기 (보통 5~60초) | 경과 시간과 중지 버튼을 보여 주고, AI가 쓰는 칸은 잠급니다. |
| 중지 · 파일 교체 · 초기화 | 진행 중인 요청을 끊고, 늦게 도착한 응답은 반영하지 않습니다. |
| 형식이 잘못된 응답 | 기존 후보와 표를 지우지 않고 그대로 둡니다. |
| 다시 받기 | 한 번 더 눌러야 바뀝니다. 직접 쓴 칸과 지운 항목 기록은 그대로 남습니다. |
| AI를 쓸 수 없는 환경 | 직접 입력과 붙여넣기, 문서 저장은 계속할 수 있습니다. |

## 8. 실행 방법

- **바로 쓰기:** [실행 사이트](https://claude.ai/artifact/AfsHiiQy4GcTfhKeuHJnB3)를 열고 리추얼 기록 JSON 파일을 올립니다.
- **로컬에서 열기:** 이 저장소의 파일을 정적 서버로 열면 화면과 직접 입력, 저장 흐름은 동작합니다. AI 버튼은 Claude 아티팩트 안에서만 동작합니다.

리추얼 기록 JSON은 `{ "student": "...", "days": [ { "date": "YYYY-MM-DD", "open": ["질문: 답"], "close": ["질문: 답"] } ] }` 형식을 기본으로 읽습니다.

## 9. 만든 과정

- **Claude**: 과제 흐름과 기능, AI 요청문, 통과 기준 점검, 구현
- **Codex**: 레이아웃·디자인 지침서 작성, 디자인, 코드 점검
- 두 AI가 각자 코드를 점검한 뒤 합의한 항목만 반영했고, 서로 승인한 뒤 최종본으로 정리했습니다. 반영하지 않은 항목과 이유는 `docs/review-decisions.md`에 있습니다.

## 10. 개인정보와 범위

- 개인 리추얼 기록과 이 도구로 만든 제출 문서는 저장소에 포함하지 않습니다.
- AI 버튼을 누를 때만 기록과 규칙이 보는 사람의 Claude 계정으로 전달됩니다.
- 이 도구는 강점에서 자기소개서 초안까지를 다룹니다. 과제 제출 화면의 "AI와 내 판단 3줄"과 "재현·통과 확인 4가지"는 포함하지 않습니다.
